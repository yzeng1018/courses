第一节

AI产品PRD和传统PRD有什么不同

3

3.1 — 一个直觉决策

你凭直觉就会做的设计

AI值机项目有一个简单的逻辑：

AI Agent去值机 → 做不了用爬虫兜底 → 实在不行用人工兜底。

这个逻辑听起来很自然。但如果你不写进PRD——

4

3.1 — 为什么要写下来

开发团队会问你一百个问题

  • AI"做不了"的标准是什么？超时算不算？报错算不算？
  • 操作到一半卡住了算不算失败？
  • 什么时候切到爬虫？什么时候切到人工？
  • 切换的时候用户知不知道？要不要通知？

传统PRD写"产品做什么"。AI产品PRD还要写"AI做不到的时候，产品做什么"。

5

3.1 — 核心差异

AI产品PRD多了三样东西

01

模型行为规格

AI应该做什么、不应该做什么、遇到边界怎么处理

02

置信度设计

AI"多确定算够确定"？不够确定时怎么呈现给用户？

03

降级策略

AI失败不等于产品失败——你的B方案和C方案是什么？

6

3.1 — 类比

换个方式理解

传统PRD

  • 像写工作说明书
  • 功能要么成功要么失败
  • 出错 → 显示错误页面

AI产品PRD

  • 像写行为准则
  • 输出有"确定"和"不确定"
  • 失败 → 优雅降级到B/C方案

3.2

第二节

模型行为规格
告诉AI什么该做、什么不该做

8

3.2 — 真实故事

AI推荐了一家关门的酒店

我自己做的AI旅行助手，让它推荐酒店。

名字、地址、描述都像模像样——但这家酒店已经关门了。

问题出在哪？

我没有定义一条规则："推荐前必须验证酒店是否还在营业。"

9

3.2 — 我怎么修的

三步修复

  • 推荐前调酒店API做一次在线验证
  • API查不到 → 不是不推荐，而是加提示："此信息可能不够准确，建议您确认"
  • 让用户自己判断，而不是假装AI一定对
10

3.2 — AI产品的取舍

但这里有一个tradeoff

准确性
每次推荐前都调API验证
确保信息正确
⇄
响应速度
多一次API调用
所有用户都多等几秒

推荐关门酒店是小众case。你要不要为了低概率事件，让所有用户都多等几秒？

11

3.2 — 核心认知

AI产品的tradeoff比传统产品多得多

传统产品的功能：要么做，要么不做。

AI产品的每一个设计决策，都在三个维度之间权衡：

🎯

准确性

结果对不对

⚡

速度

用户等多久

💰

成本

每次调用花多少钱

这些取舍必须写进PRD——不然每个开发会做不同的选择。

12

3.2 — 怎么写

模型行为规格：四个必写

部分 内容 值机案例
Must Do AI执行前必须完成的检查 确认航班号、日期、乘客匹配
Must Not 零容忍的行为 不给错误乘客值机；不选付费座位
Edge Cases 不确定时的默认行为 不认识页面 → 暂停，切爬虫
沟通规范 不确定时怎么告诉用户 "建议您确认" vs 直接给答案

第三节

置信度与降级策略

AI失败了，产品不能失败

14

3.3 — 置信度

AI有多"确定"？

AI的每一个输出，背后都有一个"它自己有多确定"的数字。

你不需要理解这个数字怎么算。但你必须决定：怎么用它。

15

3.3 — 产品决策

你需要定两条线

高

高置信度 → 直接展示

AI够确定，结果直接给用户

中

中间地带 → 展示 + 提示

"此结果仅供参考" / "建议您确认"

低

低置信度 → 不展示，走降级

AI不够确定，切换到B方案

16

3.3 — 实例

旅行助手的置信度设计

✓

酒店API验证成功

高置信度 → 直接推荐

~

酒店API查不到

低置信度 → 推荐但加提示"信息可能不准确，建议确认"

这就是一个最简单的置信度设计。不需要很复杂，但必须有。

17

3.3 — 降级策略

AI值机的三级降级

L1

AI Agent

默认方案 · 自动完成 · 最佳体验

L2

传统爬虫

AI失败/超时时触发 · 自动完成 · 覆盖率有限

L3

人工兜底

爬虫也失败时触发 · 可能有延迟 · 但一定能完成

18

3.3 — 设计原则

降级策略的三个原则

  • 对用户尽量透明 — 用户不关心后面是AI还是人，只关心值机成不成功
  • 降级不是失败 — 是体验的优雅退化
  • 最差情况的体验下限，决定了用户的信任上限

用户信不信你的产品，取决于它最差的时候有多差，而不是最好的时候有多好。

19

3.3 — 交付物

AI产品PRD模板

章节 AI产品PRD多了什么
功能需求 + 模型行为规格（Must Do / Must Not / Edge Cases）
交互设计 + 置信度分级展示规则
异常处理 + 降级策略（L1 / L2 / L3 及触发条件）
数据需求 + 模型监控指标（准确率 / 覆盖率 / 降级率）
发布标准 + 模型性能基准线（低于多少不上线）
